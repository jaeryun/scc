# 문서화 규칙

> 모든 프로젝트 문서는 한국어로 작성한다. 기술 용어, 코드 블록, 파일 경로, URL은 원문 표기를 유지한다.

---

## 언어

- [필수] **모든 문서는 한국어로 작성** — README, 가이드, 규칙, 아키텍처 문서, 코드 주석 등 프로젝트 내 모든 문서가 대상
- [필수] **기술 용어 원문 유지** — 프레임워크명, 라이브러리명, API명, 디자인 패턴명 등 고유명사는 영어 그대로 표기
  ```markdown
  React Query의 `useSuspenseQuery`는 서버 prefetch와 함께 사용한다.
  Zod 스키마로 `.parse()` 검증 후 Prisma 쿼리를 실행한다.
  ```
- [필수] **코드 블록, 파일 경로, URL 원문 유지** — 번역하지 않고 그대로 삽입
- [필수] **불필요한 서론/결론 금지** — 문서는 간결하게 핵심만 전달. "안녕하세요", "이상입니다", "잘 부탁드립니다" 등 미사여구 배제
- [권장] **마크다운 구조 유지** — 제목 계층, 코드 펜스, 들여쓰기 등 구조 요소는 번역 시에도 그대로 유지

---

## 파일 유형별 규칙

### CLAUDE.md — AI 메타데이터

- [필수] **모든 디렉토리는 CLAUDE.md를 가진다** — 예외 없음
- [필수] **최소 포함 내용**:
  1. 디렉토리의 목적 (한 문장)
  2. 포함된 파일/서브디렉토리 목록 (간략)
  3. 컨텍스트 로딩 시점 ("항상", "X 작업 시", "필요 시", "로딩 금지" 중 하나)
  4. `> 구조와 파일 목록은 @docs/<path>/index.md 참조.` 로 index.md 위임
- [필수] **구조 테이블, 결정 트리, 상세 파일 설명을 작성하지 않는다** — index.md의 역할
- [필수] **한국어로 작성** (기술 용어, 파일 경로 예외)
- [권장] **50줄 이하 유지**

  ```markdown
  # 예: 올바른 CLAUDE.md
  # <디렉토리명>/ -- <한 줄 목적>

  <간략한 설명>.

  **로딩 시점:** <항상 / X 작업 시 / 필요 시>

  - `<파일명>.md` -- <역할>
  - `<파일명>.md` -- <역할>

  > 구조와 파일 목록은 `@docs/<path>/index.md` 참조.
  ```

### index.md — 공용 탐색 & 판단 기준

- [필수] **모든 디렉토리는 index.md를 가진다** — 예외 없음. CLAUDE.md와 한 쌍
- [필수] **포함 내용**: 디렉토리 구조, 파일 목록과 링크, 결정 트리, 경계 규칙 등 탐색에 필요한 모든 정보
- [필수] **로딩 시점을 작성하지 않는다** — CLAUDE.md의 역할
- [권장] **사람과 AI 모두가 읽는다** — 마크다운 링크와 명확한 제목 계층으로 작성

### README.md — 하위 디렉토리에서 사용하지 않음

- [필수] **하위 디렉토리에 README.md를 만들지 않는다** — CLAUDE.md(index.md와 역할 분리)와 달리 README.md는 목적/구조/사용법이 하나로 합쳐져 있어 CLAUDE.md + index.md 쌍과 기능이 완전히 중복된다. 루트 `README.md`만 예외로 허용
- [권장] **루트 README.md** — 프로젝트의 얼굴로서 최소한의 소개, 기술 스택, 시작 가이드를 담는다. 상세는 `docs/`로 위임

### CLAUDE.md ↔ index.md 분리 원칙

| 내용 | 위치 | 이유 |
|------|------|------|
| 로딩 시점 | CLAUDE.md | AI 전용 메타데이터 |
| 디렉토리 목적 | CLAUDE.md | AI가 자신의 임무와 관련된 디렉토리인지 판단 |
| 파일/서브디렉토리 목록 | index.md | 구조 정보는 공용 |
| 결정 트리, 경계 규칙 | index.md | 탐색 로직은 공용 |
| 클릭 가능한 링크 | index.md | 사람도 읽으므로

### `@` 참조 vs 일반 링크

- [필수] **`@docs/...` 참조는 CLAUDE.md에서만 사용** — CLAUDE.md의 로딩 시점 정책에 따라 AI가 판단하여 로딩. 의도적으로 연결된 문서만 참조
- [필수] **index.md에서는 `@docs/...` 사용 금지** — 일반 마크다운 링크 `[link](path)` 사용. 사람은 클릭, AI는 필요 시 Read. `@` 접두사가 없어야 AI가 자동 로딩하지 않음
- [필수] **규칙/패턴 문서에서 `@docs/...` 참조는 예시 코드로만** — "CLAUDE.md는 이렇게 작성하라"는 템플릿 내부에만 허용

### 규칙 파일 vs 패턴 파일 — development/ 내부 구분

- [필수] **파일명으로 성격을 구분한다** — `development/` 아래에는 두 종류만 존재:

  | 파일명 패턴 | 성격 | 예시 |
  |-------------|------|------|
  | `*.md` (접미사 없음) | **규칙** — 반드시 지켜야 함, 위반 시 버그 또는 리뷰 거절 | `react.md`, `forms.md`, `naming.md` |
  | `*-patterns.md` | **패턴** — 권장 접근법, 코드 예제, 복사해서 쓰는 템플릿 | `form-patterns.md`, `component-patterns.md` |

- [권장] **모든 항목에 `[필수]`/`[권장]` 태그** — `[필수]`는 위반 시 PR 승인 불가, `[권장]`은 원칙적 준수, 예외 가능

### 그 외 일반 문서

- [필수] **파일명 kebab-case** — `data-layer.md`, `build-deploy.md`, `component-patterns.md`
- [권장] **한 파일에 한 주제** — 여러 주제를 한 파일에 섞지 않는다. 주제가 커지면 여러 파일로 분리
- [권장] **코드 예제는 실제 프로젝트 코드에서 발췌** — 가상의 예제보다 `src/`에 실제 존재하는 코드를 인용

## 디렉토리 구조

- [필수] **디렉토리별 역할 분리** — 아래 구조를 준수한다:

  | 디렉토리 | 목적 | 배치 규칙 |
  |-----------|---------|-----------|
  | `docs/common/foundation/` | 프로젝트 헌장 (정체성, 제약, 핵심 결정) | 플랫 |
  | `docs/common/development/` | 코딩 규칙 + 구현 패턴 — 모든 코드 작성 가이드 | 플랫 (하위 디렉토리 금지) |
  | `docs/common/operations/` | 빌드, 배포, 장애 대응, 모니터링 | 플랫 |
  | `docs/common/reference/` | API, 데이터 모델, env 변수 | **하위 디렉터리 허용 (유일)** |
  | `docs/common/decisions/` | 아키텍처 결정 기록 (ADR) | 플랫, 시간 순 |
  | `docs/views/` | 뷰별 도메인 지식 | `views/<view>/` |
  | `docs/archive/` | 과거 산출물 | 로딩 금지 |

- [필수] **`reference/`만 하위 디렉터리 허용** — 카탈로그 성격이라 그룹핑 없이 평탄하면 탐색 불가. 다른 디렉토리는 하위 디렉토리 생성 금지
- [필수] **`reference/` 하위 디렉토리 생성 기준**: 해당 주제의 파일이 3개 이상 예상될 때만. 1-2개는 `reference/` 루트에 플랫하게
- [필수] **`docs/archive/` 읽기 금지** — AI 에이전트는 절대 `docs/archive/`를 읽지 않는다

## views/ vs common/ 경계

- [필수] **계약 vs 사용법으로 판단한다**:

  | 문서 성격 | 위치 | 예시 |
  |-----------|------|------|
  | 계약/스펙 (데이터 구조, API 입출력) | `common/reference/` | IPAM API 명세, Subnet 타입 정의 |
  | 규칙/패턴 (코드 작성 방법) | `common/development/` | "TanStack Form 작성법" |
  | 워크플로우/사용법 (특정 뷰의 작업 절차) | `views/<view>/` | "DCIM에서 서브넷 추가하는 법" |

- [권장] **애매하면 좁은 범위에 먼저** — `views/<view>/`에 두고, 실제 공유 필요가 생기면 `common/`으로 승격. `git mv` + 참조 경로 수정만 하면 됨

## AI 에이전트 지침

- [필수] **`@docs` 접두사** — `@docs`는 항상 프로젝트 루트의 `docs/` 디렉토리를 가리킨다
- [필수] **요청 시에만 문서 생성** — 사용자가 명시적으로 요청한 경우에만 새 문서 파일을 생성. 자발적 문서 생성 금지
- [필수] **기존 문서 수정 최소화** — 현재 작업과 직접 관련된 부분만 수정. 인접 섹션 "개선" 금지
- [권장] **문서 현행화** — 동일한 실수 2회 발생 시 관련 문서에 규칙 추가
