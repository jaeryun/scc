# 문서 작성 공통 규칙

## 언어

- [필수] **한국어로 작성, 기술 용어/코드 블록/파일 경로/URL은 원문 유지** — 프레임워크명, 라이브러리명, API명 등 고유명사는 번역하지 않는다

## `@` 참조와 일반 링크

- `@` 참조 — AI 자동 로딩 대상 파일(CLAUDE.md, `.claude/rules/*.md`)에서만 사용. AI가 해당 파일을 자동으로 컨텍스트에 로딩. `@` 경로는 해당 참조가 포함된 파일 기준 상대경로
- 일반 마크다운 링크 (`[link](path)`) — index.md, 일반 문서에서 사용. 사람이 클릭해서 탐색, AI는 필요 시에만 Read. 자동 로딩되지 않는다

## AI 지침과 사람 규약의 경계

- **CLAUDE.md** — 주로 AI 대상 (로딩 정책, 행동 지침). 파일 배치 규칙 등 사람도 참고할 수 있는 정보를 포함한다. 핵심 로딩/행동 지침이 주 목적.
- **index.md** — 사람 + AI 공유: 디렉터리 구조, 파일 배치 규칙, 디렉터리 경계 기준. 순수 AI 로딩 지시("~에서 로딩됩니다", "~에서 읽지 않습니다")만 제외하고, 문서 배치/구조에 대한 규약은 index.md에 작성한다.
- **일반 .md** — 사람 + AI 공유: 순수 AI 지시를 제외한 기술 문서

## 일반 문서 규칙

- [필수] **규칙 vs 패턴 파일명 구분** — `*.md` (접미사 없음)는 규칙, `*-patterns.md`는 권장 패턴. 상세는 [development/index.md](../development/index.md)의 "파일 구분" 섹션 참조
- [필수] **파일명 kebab-case** — `data-layer.md`, `build-deploy.md`
- [권장] **한 파일에 한 주제** — 여러 주제를 섞지 않는다
- [금지] **프로젝트 외부 코드를 문서화하지 않는다** — 문서화 대상은 이 프로젝트에서 직접 작성한 파일로 제한. `node_modules/`, `.next/`, `dist/`, 생성된 코드, 서드파티 라이브러리 내부 파일 등은 제외
- [권장] **코드 예제는 실제 프로젝트 코드에서 발췌** — 가상 예제보다 `src/`에 실제 존재하는 코드를 인용
